## Sherlock Scenario
In this Sherlock, you will familiarize yourself with Unix auth.log and wtmp logs. We'll explore a scenario where a Confluence server was brute-forced via its SSH service. After gaining access to the server, the attacker performed additional activities, which we can track using auth.log. Although auth.log is primarily used for brute-force analysis, we will delve into the full potential of this artifact in our investigation, including aspects of privilege escalation, persistence, and even some visibility into command execution.
***

In this sherlock we're going to use my tool [sshf](https://github.com/Nurimy97/sshf). It filters ssh logs and organizes them into a table with colors to better visibility.

### Task 1
- Analyze the `auth.log`. What is the IP address used by the attacker to carry out a brute force attack?

Filtering with sshf by logins can be easily spotted looking for red lines:
```bash
sshf -f auth.log -l login
```
### Task 2 
- The bruteforce attempts were successful and attacker gained access to an account on the server. What is the username of the account?

Now we can find the successfull logins filtering by "Accepted".
```bash
python sshf.py -f /home/nurimy/auth.log -l login -s Accepted
```
In order to find the username we have to find the first login matching the ip from the previous task.
### Task 3
- Identify the UTC timestamp when the attacker logged in manually to the server and established a terminal session to carry out their objectives. The login time will be different than the authentication time, and can be found in the wtmp artifact.

Let's play with the python script included in the .zip. Use it with the wtmp file. Filter by the ip of the attacker and take the timestamp from the first entry.
```bash
python utmp.py wtmp | grep [attacker ip]
```
### Task 4
- SSH login sessions are tracked and assigned a session number upon login. What is the session number assigned to the attacker's session for the user account from Question 2?

Using sshf, filter now by the user from question 2 and look for the session number that is shortly after the "Accepted Password".
```bash
python sshf.py -f /home/nurimy/auth.log -s root
```
### Task 5 
- The attacker added a new user as part of their persistence strategy on the server and gave this new user account higher privileges. What is the name of this account?

If we filter by *useradd* we'll find the user easily.
```bash 
python sshf.py -f /home/nurimy/auth.log -s useradd
```
### Task 6 
- What is the MITRE ATT&CK sub-technique ID used for persistence by creating a new account?

Look for "MITRE ATT&CK creating a new account" in google, enter the *MITRE ATT&CK* and look for the sub-technique *Local Account*
### Task 7
-What time did the attacker's first SSH session end according to auth.log?

Here we can do the same that in task 5 and take the timestamp.
```bash 
python sshf.py -f /home/nurimy/auth.log -s [user]
```
### Task 8 
- The attacker logged into their backdoor account and utilized their higher privileges to download a script. What is the full command executed using sudo? 

The last task, we only have to use the sudo filter and look for the command.
```bash 
python sshf.py -f /home/nurimy/auth.log -l sudo
```
